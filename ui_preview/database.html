테이블 관계 한눈에 보기

한 가지 맛에는 여러 주문이 연결되고, 한 주문에는 여러 오류 기록이 연결될 수 있습니다.

icecream_flavor
맛 1개1 → N order_history
주문 여러 개1 → N error_log
오류 여러 개

1. icecream_flavor 맛 정보

키오스크에 표시할 아이스크림 맛과 판매 가능 여부를 저장합니다.

컬럼자료형의미제약/예시
idINTEGER맛 고유 번호PK · 자동 증가
nameVARCHAR(50)맛 이름UNIQUE · 바닐라, 초콜릿, 딸기
is_availableBOOLEAN현재 주문 가능 여부기본 TRUE

2. order_history 주문 내역

고객 주문과 로봇의 제조 진행 상태를 저장하는 중심 테이블입니다.

컬럼자료형의미제약/예시
idINTEGER주문 번호PK · 자동 증가
flavor_idINTEGER주문한 맛 번호FK → icecream_flavor.id
statusVARCHAR(20)주문 처리 상태PENDING / PROCESSING / COMPLETED / FAILED
ordered_atTIMESTAMPTZ주문이 접수된 날짜와 시각기본 CURRENT_TIMESTAMP
PENDING
주문 대기→PROCESSING
로봇 동작 중→COMPLETED
제조 완료

실패 흐름: 제조 중 문제가 발생하면 상태가 FAILED로 바뀌고 상세 내용은 error_log에 저장됩니다.

3. error_log 오류 기록

어떤 주문의 어느 로봇 단계에서 무슨 오류가 발생했는지 저장합니다.

컬럼자료형의미제약/예시
idINTEGER오류 기록 번호PK · 자동 증가
order_idINTEGER오류가 발생한 주문 번호FK → order_history.id · 주문 삭제 시 함께 삭제
process_stepVARCHAR(50)오류가 발생한 제조 단계CUP_PICK, SCOOP_ICECREAM, SERVE_CUP 등
error_codeVARCHAR(50)오류 종류GRIP_FAILED, MOVE_FAILED 등
messageVARCHAR(255)사람이 읽을 수 있는 상세 설명필수 값
created_atTIMESTAMPTZ오류 발생 날짜와 시각기본 CURRENT_TIMESTAMP

실제 데이터가 연결되는 예

딸기
flavor id = 3→주문 #12
status = PROCESSING→이동 실패
MOVE_FAILED

추후 확장: 로봇의 단계별 진행률을 DB에 저장할 때 order_history에 current_step 컬럼을 추가할 예정입니다.
